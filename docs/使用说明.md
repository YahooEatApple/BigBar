# BigBar v1.1.4 使用说明

一个常驻桌面的大号滚动条：屏幕边缘一条看得见、点得中的滚动控制条，滚动的永远是你**最后一次点击的那个窗口**。



***

## 一、安装



1. 双击 `BigBar-Setup-1.1.4.exe`

2. 点「安装」，默认装到：`%LocalAppData%\Programs\BigBar`

3. 装完自动生成桌面 + 开始菜单快捷方式「BigBar」，并写入开机自启

4. 装完即用：滚动条立刻出现在屏幕右侧，开机自动启动

卸载：设置 → 应用 → 「BigBar」→ 卸载；或运行安装目录里的 `Uninstall.exe /uninstall`



***

## 二、四个分区怎么用

滚动条从上到下只有四个区，宽度一致、零间隔：**A（顶）→ F（轨）→ B（底）**，滑块 K 在轨道里。皮肤文件里的区块名对应：`pageup` = A、`track` / `upper-track` / `lower-track` = F（可拆上下两段）、`pagedown` = B、`thumb` = K（旧名 `A` / `F` / `B` / `K` 仍然兼容）。



| 区域    | 位置    | 单击                                                                | 双击         |
| ----- | ----- | ----------------------------------------------------------------- | ---------- |
| **A** | 最顶部   | **自动向上**滚动，每秒约 10%，到顶自动停；再单击一次立即停                                 | 直接跳到**顶部** |
| **F** | 中间长条  | 滑轨。直接点击轨道可跳到该位置；整条拖动可改高度（仅「调整模式」下可改）。皮肤写了 `upper-track` / `lower-track`（旧名 `F1` / `F2`）时轨道分上下两段（交界在 K 的中间） | 同左         |
| **K** | 轨道内滑块 | 点一下可停下正在进行的自动滚动；**按住拖动**页面跟着实时滚动，位置就是当前滚动比例                       | 同左         |
| **B** | 最底部   | **自动向下**滚动，每秒约 10%，到底自动停；再单击一次立即停                                 | 直接跳到**底部** |

要点：



* 滚动的对象永远是「最后一次鼠标点击的窗口」—— 多窗口时不会乱，点一下目标窗口再操作滚动条即可

* A/B 一个按钮两种用法：**单击 = 慢速自动滚**，**双击 = 一步到顶 / 到底**

* 豆包桌面版这类「读不到滚动位置」的窗口，单击 A/B 用 **30%/ 秒**（读得到位置的普通程序是 10%/ 秒），且不会自己停在端点，要再点一次才停

* 位置 / 高度调整统一走「菜单 → 高度 自定 或 横向 / 纵向距离 自定义 → 调整模式 → 确定 / 取消」，非调整状态下四区点击与 K 拖动都可用，绝不会误拖

* **菜单打开后，点菜单外任何一处它就收起来**：点工具本体、点其它应用、点桌面都算「外面」；右键点工具弹出菜单，再右键点工具就是收起（不会又弹一个新的）；点菜单内部（含二级皮肤面板、透明度进度条）不受影响

* 顶部 / 底部的 C、D 两个缓滚区已合并进 A、B（即 `pageup` / `pagedown`），整条更短、更好点

* 鼠标指针由皮肤里的 `cursor` 决定：默认是移到 **A / B / K** 手形、**按住拖动 K** 手形（拖出条外也一样）、松手回手形、滑轨与空白处普通箭头；调整模式（锁定位置后）仍按原规则：上下边缘上下箭头、中间移动箭头

* **永远在所有应用之上**：条是置顶窗口，并且每 300ms 核对一次层级——只要有别的「置顶 / 全屏」窗口盖到条上，就立刻把自己抬回最顶层（不抢焦点、不激活），菜单打开时顺序是「菜单 → 条 → 别的应用」。全屏独占的游戏（DirectX 独占全屏）由系统接管显示，任何普通窗口都盖不上去，这类场景请把游戏改成「无边框窗口」模式

### K 的位置会跟着目标窗口的真实滚动条走

点中一个带滚动条的目标窗口后，K 会立刻按该窗口**当前滚动条的真实位置**重算比率，滑块高度比例与目标滚动条一致，不会停留在上一个窗口的状态：



| 目标类型                                          | 比率怎么读                                                         | 实测结果                                                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 记事本 / Notepad++ / 绝大多数 Win32 程序（Word、Foxit 等） | 读子控件原生滚动信息 `GetScrollInfo(SB_VERT)`                           | 记事本、Notepad++ 实测点击后 K 立即对齐（如 Notepad++ 滚到底→点进去，K 到 1.000）                                                                 |
| Chrome / Edge / WebView 页面                    | 走 UI Automation 的 `ScrollPattern`，`VerticalScrollPercent` 即比率 | Chrome 页面实测：点进去（页面在 50%）→ K 同步 0.500；该页面再滚到 85% → K 自动跟到 0.850                                                            |
| 部分 Electron 应用（如豆包桌面版）                        | 窗口不暴露任何可读滚动位置                                                 | 日志记「K 同步 读取失败（改用滚轮相对累计）」，此时 K 只当**相对指示**：单击 A/B 按 **30%/ 秒**折算成滚轮一路滑（到边不自动停，再点一次才停；实测豆包桌面版内容确实在动），双击 A/B 连发滚轮跳到上方 / 下方一大段 |

同步是双向的：目标窗口自己滚动（滚轮、键盘、脚本）时，K 也会按新位置重新计算并跟随；K 拖动、A/B 自动滑动期间暂停读取，避免打架。

### 拖动 K 会让目标窗口真的滚动

拖动 K（以及 A/B 的单击自动滑动、双击跳顶 / 跳底）时，程序会把动作发给**真正能吃下滚动的那个窗口**，再不只是顶层外壳：



| 目标类型                             | 把滚动发给谁                                                       | 实测结果                                                 |
| -------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| 记事本 / Notepad++ 等                | 持有滚动条的内层控件（`RichEditD2DPT` / `Scintilla`）                    | 记事本拖 120px：0 → 0.613；Notepad++ 拖 120px：0.980 → 0.612 |
| Chrome / Edge / Electron（豆包桌面版等） | 顶层窗口里的 `Chrome_RenderWidgetHostHWND` 渲染窗口，滚轮点用「最后一次点击目标的那个点」 | Chrome 拖 120px：页面 50% → 57.79%；豆包侧栏拖 150px：列表实际滚动了   |
| 顶层与内层都没有滚动信息                     | 退回原始目标窗口发滚轮                                                  | 豆包桌面版拖动可直接滚内容                                        |

拖动的方向与目标滚动条方向一致：K 往下拖，目标内容往下滚（页面比率变大）。

## 三、右键菜单

在滚动条上按**右键**，旁边弹出圆角菜单（背景 #f9f9f9）：



| 菜单项 | 说明 |
| --- | --- |
| **皮肤**（菜单第 1 行） | 行标题固定是「皮肤」，**右侧直接显示当前皮肤名 + 二级菜单箭头**（名字按界面语言取皮肤 `language`，没写就退回 `name`）。点开是皮肤列表：默认皮肤 / 小狗旺旺 / 北国风光 / … / 添加皮肤…；**选中任意皮肤后，主菜单和二级菜单一起收起**（选「添加皮肤…」时先收起菜单与二级列表，再弹出「添加皮肤」窗口） |
| **宽度** | 二级菜单：**默认 / 大 / 中 / 小**，行右侧显示当前档 + 箭头。条宽取皮肤 `tool.style.width` 里对应的 `default` / `large` / `medium` / `small`，皮肤没写该档就退回 `default`；皮肤完全没写宽度才用系统默认 **100px**。优先级：**用户在菜单里选的档 > 皮肤 `default` > 系统默认**。选中即生效并收起菜单 |
| **高度** | 二级菜单：**默认 / 大 / 中 / 小 / 自定**。前四档取皮肤 `tool.style.height` 的 `default` / `large` / `medium` / `small`（像素或百分比，百分比相对屏幕工作区高度），结果永远被皮肤 `limit`（`max-height` / `min-height`）夹住：超了压回上限、不够抬到下限（系统默认上限 100% 工作区、下限 300px）。选 **`自定`** 立刻进入「调整模式」（见下） |
| **位置** | 二级菜单：**默认 / 右中 / 右上 / 右下 / 左中 / 左上 / 左下 / 自定**。`默认` 取皮肤 `tool.style.position` 的 `default`（`right-center` / `right-top` / `right-bottom` / `left-center` / `left-top` / `left-bottom`，没写就是 `right-center`）；六个固定方位直接按「贴哪一边 + 竖直对齐」摆放；`自定` 进入「调整模式」，用手把条拖到任意位置（确认后这一行就停在「自定」） |
| **横向距离** | 二级菜单：**默认 / 大 / 中 / 小 / 自定义**，行右侧显示当前档 + 箭头。横向距离＝工具离**所选屏幕左右侧**的间距，取皮肤 `tool.style.distance-x` 的 `default` / `large` / `medium` / `small`，可写像素也可写百分比（`%` 按工作区**宽**算）；皮肤没写就整组退回 `default`，全都没写用系统默认 **30px** |
| **纵向距离** | 二级菜单：**默认 / 大 / 中 / 小 / 自定义**，行右侧显示当前档 + 箭头。纵向距离＝工具离**所选屏幕上下侧**的间距，取皮肤 `tool.style.distance-y` 的四档，可写像素也可写百分比（`%` 按工作区**高**算），系统默认 **30px**。横向与纵向**各自独立生效**（例如右边距 50px、顶边距 0px 可以同时成立）；两行里任一选 **`自定义`** 都进入「调整模式」 |
| **调整模式**（由「高度 自定」或「横向/纵向距离 自定义」进入） | 菜单收起、滚动功能暂停，鼠标移到条上变成四向箭头，可拖动改位置（四周不超出屏幕）；移到条的顶部或底部边缘变成上下箭头，拖动可改高度（拖上边缘时底边不动，拖下边缘时顶边不动）。**调整框就在工具本身**：沿条的外缘画 **10px 宽绿色实线框**（`RGB 34,160,84`），框内整片蒙一层**黑色 50% 蒙层**（`ARGB 128,0,0,0`）——这层是**浮在工具之上的编辑层**，鼠标压在上面只认「确定 / 取消」和拖动，**绝不会触发下面的 A / B / K / F 按钮**；框内**水平、垂直居中**放两个**上下排列**的**圆形图标按钮**：上面 **确定**（草绿圆 `#7CB342` + 白色对勾 ✓），下面 **取消**（白色圆 + 浅灰细边 + 深灰叉 ✕）；鼠标移到这两个图标上时光标保持**系统默认箭头**（不做手形提示）。点**确定**保存当前位置与高度（位置档变「自定」、两轴距离档变「自定义」，高度只有真的改了才变「自定」）；点**取消**回到进入调整前的位置、高度与距离档。调整状态下**工具内所有区块按钮一律不可点击**（点 A/B/K/F 都不翻页、不跳转、不拖动），**右键也不再弹菜单**，只能用「确定 / 取消」结束调整 |
| **透明度** | 右侧直接是一条 **0–100 的进度条**（青色已填充段 + 白色圆点），长度约为行宽的 70%，**右端与其它行右侧对齐**，按住圆点或点任意位置即可设置，拖动时工具实时变透明，松手保存；**行内不显示百分比数字** |
| **声音** | 右侧 开 / 关 两个按钮，当前状态高亮；14 种状态的音效由皮肤预设，不单独设置 |
| **隐藏** | 点击整行就把工具收起来（托盘里第一项随之变成「显示滚动条 / Show scrollbar」，再点即可恢复）。**全局快捷键 Ctrl+Alt+S 已取消**，显示/隐藏只走菜单与托盘 |
| （无「置顶」行） | 菜单里**已经去掉「置顶」这一行**：工具**永远维持最高置顶**，不再提供关闭入口（置顶守护每 300ms 复查一次，被别的置顶/全屏窗口盖住就立刻抬回最顶层，不抢焦点）。注册表 `TopMost` 键保留，但运行中一律按「开」处理；独占全屏的 DirectX 游戏/播放器除外 |

**菜单共 9 行**（皮肤 / 宽度 / 高度 / 位置 / 横向距离 / 纵向距离 / 透明度 / 声音 / 隐藏），宽 **380** 逻辑像素（上一版 430，收窄以免挡住工具），每行 46。

**尺寸类二级菜单的交互**：宽度 / 高度 / 位置 / 横向距离 / 纵向距离 都是**二级菜单**（不在行内排分段按钮）：行名在左、**当前值靠右、右边再跟一个箭头**（`›`），列表在工具的另一侧展开；**列表第一项与刚刚选中的那一行垂直对齐**（皮肤列表是例外，仍从主菜单顶边开始排）。**鼠标移到这一行就自动展开**（约 90ms 后），**移开（离开该行且不在二级面板里）就自动收起**；点击行也照样能展开 / 收起，两条路径都通。选中任一档即生效，并**主菜单 + 二级菜单一起收起**；列表里的档位用全称（大 / 中 / 小 / 右中 / 右上 …），不会因为简写看不懂。

托盘图标（屏幕右下角）双击也能打开同一个菜单：显示/隐藏滚动条（不带快捷键后缀） / 菜单皮肤 / **语言（English / 中文 / Español，当前语言打勾，默认 English）** / 开机自启 / 使用说明 / 退出（文本随语言切换）。语言子菜单已从右键菜单**移到托盘**，切换后菜单与托盘的文案整体更换并写入注册表 `Lang`（0=中文 / 1=English / 2=Español）。**「使用说明」点击后直接用浏览器打开 <https://yahooeatapple.github.io/BigBar>**。

**菜单的弹出方向**：主菜单永远往「工具的另一侧」展开（工具贴屏幕右边时菜单在左边，反之在右边）；皮肤的二级列表再往同一侧继续展开，**不会压到、也不会出现在工具那一侧**——只有当屏幕那一侧真的没有空间时才退回，并夹在屏幕内。

## 四、皮肤系统

三套内置皮肤首次运行自动写到：`%AppData%\BigBar\skins\*.skin`



* `默认皮肤.skin` —— 对齐参考图：A/B 深灰、F 白轨道、K 青色滑块（单击变半透明、双击闪青、到顶到底变暗）

* `小狗旺旺.skin` —— **图片皮肤**：A=`小狗旺旺/ab_top.png`（up1+down1 拼成的整块，123px 高）、B=`小狗旺旺/ab_bottom.png`（down2+up2，123px）、K=`小狗旺旺/d3.png`、F=`小狗旺旺/mid.png`；K 向上拖动换 `d1.png`、向下拖动换 `d2.png`；A/B 双击闪 `d3.png`

* `北国风光.skin` —— 浅蓝冷色系

`.skin` 默认是 **JSON 格式**（记事本可改，保存后在菜单里重新选一次皮肤即生效）：



### 添加皮肤（按皮肤编号从官网下载更新）

菜单 → 皮肤名那一行 → 二级列表最后一项「添加皮肤…」，会弹出新的「添加皮肤」窗口：

* **上面一行**：`皮肤编号：` 加一个输入框，**最多只能输入 16 个字符**（字母、数字、`-`、`_`；其它字符会直接提示非法）；
* **下面一行**：左侧「下载并更新」，右侧「关闭」；输入框里按回车等同点「下载并更新」；
* 点「下载并更新」后按 `http://www.bigbar.me/skin/<皮肤编号>` 取压缩包（超时 15s、上限 40MB），**解压到真实生效的皮肤目录** `%AppData%\BigBar\skins`（注意：不是程序安装目录，程序只读这个目录里的皮肤），**同名文件直接覆盖**，所以本地已有同套皮肤时就是「更新皮肤及其图片等文件」；
* 包里如果多套了一层外壳目录（`xxx/某某.skin` + `xxx/某某/图片…`），会把外壳整层上提，保证 `.skin` 落在 `skins` 根目录、图片相对路径仍然成立；
* 更新完成后立即重读皮肤目录，**如果这次更新的正好是当前在用的皮肤，会马上重新加载生效**；提示行会用绿字报出本次更新的皮肤名与写出的文件数；
* 失败提示分三类：`HTTP 404` → 「没有这个皮肤编号」；服务器返回网页而不是压缩包 → 「服务器返回的不是皮肤压缩包（编号不存在或网站还没上线）」；网络超时/连不上 → 「下载失败：…」。失败不影响本地已有皮肤；
* 解压带 zip-slip 防护，包里出现 `../` 这类越界路径的条目会被跳过；压缩包用的是 `DeflateStream` 手写解析，不依赖 .NET 4.5 的 `ZipFile`，Win7 SP1 也能用。



### 已移除：白天 / 黑夜配色（`-night` 键）

昼夜切换已**整体去掉**：程序不再检测系统是白天还是黑夜，菜单里也没有「日夜」行。旧皮肤里的 `-night` 键会被忽略（读到时不再参与渲染），保存皮肤时也不会再写出来——写在新皮肤里属于无用字段。

> **换肤即重载**：每次在菜单里选皮肤，程序都会重新从磁盘读取 `.skin` 文本**和它引用的每一张图片**（不吃内存里的旧缓存）。所以改皮肤、换图、乃至新放一套 `.skin` 进目录，都不必重启程序 —— 打开菜单（列表会重扫目录）再选一次即可。

### 皮肤名的多语写法（`language` 键）

界面语言支持**中文 / English / Español** 三种。皮肤可以在顶层写一组 `language`，给同一套皮肤准备三种语言的显示名 —— 菜单第 2 行的皮肤名、皮肤二级列表里的名字，都会跟着当前界面语言走：

```
{
  "name": "Apple",
  "language": { "en": "Apple Style", "zh": "苹果风格", "es": "Estilo Apple" },
  "author": "",
  "width": "100px",
  ...
}
```

| 键 | 说明 |
| --- | --- |
| `language.en` | 界面语言为 English 时显示的皮肤名 |
| `language.zh` | 界面语言为中文时显示的皮肤名 |
| `language.es` | 界面语言为 Español 时显示的皮肤名 |

**回退规则**：某个语言没写 → 先用 `en`，再 `zh`，再 `es`，最后退回顶层的 `name`。所以只写 `en` 也能正常显示，不会出现空名字。

> **`name` 仍是皮肤的身份证**：注册表 `Skin` 值、`添加皮肤`、音效目录、删除皮肤都按 `name` 走。`language` 只是「显示名」，改 `name` 等于换了一套皮肤（旧注册表值会失效），改 `language` 不影响任何既有设置。

> 三套自带皮肤自带三种语言名（默认皮肤 / Default / Predeterminado，小狗旺旺 / Puppy / Cachorro，北国风光 / Northern Light / Luz del Norte）。

### 你自己的皮肤不会被自动改写（`generatedby` 标记）

程序生成的皮肤文件，第一行 `name` 后面会带一个标记：

```
"generatedby": "gunbar",
```

启动时`自带皮肤自动升级`只认这个标记：

| 文件情况 | 程序行为 |
| --- | --- |
| 文件不存在 | 写出整套自带皮肤 |
| 文件解析失败（写坏了） | 备份成 `*.bakN` 后重建一份好用的 |
| **带 `"generatedby": "gunbar"`** | 缺夜景键 / 缺 `language` 时才升级（升级前先备份 `*.bakN`） |
| **没有这个标记** | 一个字节都不动，只往日志里写一行「跳过自带皮肤升级（不是本程序生成，保持原文件）」 |

也就是说：只要你自己改过 `%AppData%\BigBar\skins\` 里任意一个 `.skin`（改颜色、换图片、加 `language`），它就不再属于「自带皮肤」，以后升级版本也不会被覆盖。

> 这条规则是踩坑换来的：早期版本只按文件里有没有「官方」两个字来认自带皮肤，结果把你自己改的 `北国风光.skin`（作者也写着「官方」、宽 100、引用了 15 处图片）当成自带皮肤重写了，重写成宽 74、无图的简化配色版。改按 `generatedby` 标记判断后，这类覆盖不会再发生。

规则：

* **优先级 = 用户在菜单里的设定值 > 皮肤 `default` 值 > 系统默认值**（宽度系统默认 100px、高度 70%、位置 `right-center`、横向/纵向距离各 30px）
* 位置由两段决定：**贴哪一边**（left / right）+ **竖直怎么对齐**（top / center / bottom），六个方位就是这两段的六种组合
* 高度最后一步永远按 `limit` 收口：超过 `max-height` 压回上限，低于 `min-height` 抬到下限；若两者矛盾（例如 `min-height` 大于 `max-height`），先压上限再抬下限，最后收进工作区
* 高度兜底：皮肤完全没写高度、用户也没设过时，整条高度 = 70% 工作区；如果这个高度连 A+B+K+间距 都装不下，会自动抬到刚好装下
* 进过「调整模式」点过**确定**：位置记为「自定」，横向、纵向距离都记为「自定义」，之后按那次的手拖坐标摆放；高度只有真的改了才变「自定」
* 换皮肤同时会刷新鼠标指针与悬停/按下/拖动状态，不会残留上一套皮肤的样式
**图片排版（CSS 三件套，写在&#x20;**`style`**&#x20;上）**



| 字段                             | 取值                                                                                                                     | 不写时的效果                                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `background-repeat`            | 只认 CSS 标准四值：`no-repeat` 单张 / `repeat-x` 横向平铺 / `repeat-y` 纵向平铺 / `repeat` 双向平铺（旧写法 `x`、`y`、`horizontal`、`vertical`、`both` 已取消，写了视为未设） | 单张（不平铺）                                         |
| `background-size`              | `auto` 保持图片原始像素 / `cover` 放大到铺满该区（超出部分裁掉）/ `contain` 缩小到完整装进该区 / **两值写法** `100% auto`、`auto 120px`、`60px 40px` | 不写 `size` 也不写 `repeat` = **拉伸铺满整块**（旧皮肤行为，向后兼容） |
| `background-position`          | 两段值，如 `left top` / `center center` / `center bottom` / `50% 50%`；**也支持像素 / 百分比偏移（可为负）**：`0px 0px`、`30px 20px`、`-100px -80px`、`-20% -10%`；也可分开写 `background-position-x`、`background-position-y` | `left top`                                      |
| `background-position-x` / `-y` | **关键字**（`left`/`center`/`right`、`top`/`center`/`bottom`）或 **像素 / 百分比偏移**：`0px`、`30px`、`-8px`、`25%`                     | 该轴按 `left` / `top` 对齐                           |

要点：



1. 写了 `background-size`，或只写了 `background-repeat`（按 CSS 语义自动按原始尺寸平铺），才进入「排版模式」；两个都不写就是老行为「一张图拉伸铺满」，所以老皮肤外观不变。**只写了像素 / 百分比偏移（**`background-position-x: 0px`**）也算排版模式**，会按图片原始尺寸摆放。

2. 平铺时 `background-position` 决定第一块贴图的对齐起点（例如 `repeat-y` + `center center` 让纵向条带水平居中）；写成像素值时，就是在关键字对齐的基础上**再平移**（`repeat` 下等于把平铺起点整体挪一段）。

3. 图片一律裁剪在该区范围内，`cover` 或多块平铺都不会溢出到相邻区域。

4. 示例：滑轨 F 用一条 100×31 的草带纵向铺满 —— `"background-image": "url(小狗旺旺/down2.png)", "background-repeat": "repeat-y", "background-size": "auto", "background-position": "center center"`。

5. 渐变和贴图互斥：同一区写了 `linear-gradient` 就不再贴 url 图（先写 `background-image` 的贴图时以贴图为准）。

6. **像素是按皮肤基准宽度换算的**：皮肤 `tool.style.width` 的 `default` 是 `100px` 时，`10px` 偏移就占条宽的 1/10，条被拉宽（宽度档 L / M / S、或自定调整）时偏移同比缩放，不会因为放大而错位。百分比永远按该区自身高度 / 宽度算，`25%` 就是「区高的 1/4」。负值向左 / 向上移。

7. **`background-size` 两值写法（与 CSS 一致）**：`100% auto`、`auto 100%`、`60px 40px`。第一段是宽、第二段是高，`auto` 那一段按图片原始比例算：
   - `100% auto`：宽铺满该区，高按比例放大 → 图不会被压扁，配 `background-repeat: "repeat-y"` 就是等比例纵向平铺（这是做「整条轨道纹理」最常用的写法）。
   - `auto 120px`：高固定 120px，宽按比例。
   - `60px 40px`：宽高都写死（会变形，慎用）。
   - `100% 100%`：整个区拉伸（等于老行为，但只作用于该区）。
   百分比按该区宽度 / 高度算，`px` 按皮肤基准宽度换算；数值写法生效后，`background-repeat` 就正常平铺（旧版把 `100% auto` 当「未设」处理，直接拉伸铺满并忽略 `repeat`，已修复）。

8. **`cover` + `no-repeat` + `background-position: "0px 0px"` 这一组是可用的**（实测验证）：先按 `cover` 等比放大到刚好盖满该区（放不下的部分裁掉，裁剪只在该区内、不会溢出相邻区），再按 `position` 定位；`"0px 0px"` 等价于 `left top`，即从该区左上角开始，只出现一张、不平铺。整块图当背景的推荐写法：
   `"background-image": "url(小狗旺旺/bigbar1.png)", "background-repeat": "no-repeat", "background-size": "cover", "background-position": "0px 0px"`（或直接写 `"background-position": "left top"`，两者等价）。

9. **负偏移可用**：`"background-position": "-100px -80px"` 表示从该区左上角起，图片再向左平移 100px、向上平移 80px，超出该区的部分被裁掉（和 CSS 一致，用来做“只露出图片右下一块”的效果）。像素、百分比都可以为负（`-20% -10%`）；只写一个负值（`-100px`）就是只做横向平移。单独写 `background-position-x` / `background-position-y` 的负值同样有效。不写 `background-size` 时会自动按原始像素摆放（拉伸铺满时偏移没有意义）。

10. **一张图放多套状态（图集 / sprite）要用** **`auto`**，不能用 `cover`：

   * `"background-size": "auto"` —— 图片按**原始像素 1:1** 画出来，用 `background-position` 去「选格」，超出该区的部分自动裁掉。图集（例如 300×320 里 3 列 × A/K/B 三段）必须这样写，才只显示你要的那一格。
   * `"background-size": "cover"` —— 按 CSS 语义**等比缩放盖满该区**。把 300 宽图集塞进 100 宽的区域时，整张图被压成 100 宽，结果是「三列同时出现在一条 100 宽的条上」（就是图中出现三列、每列一个圆点的那个错样）。
   * 等价写法：`"background-size": "100px 320px"`（宽高都写死，按原像素铺）。
   * `auto` 的像素按 DPI 换算，100px 的图在 125% 缩放下占 100 个逻辑像素（正好等于 100px 的条宽），所以在任何缩放比例下都是 1:1 裁切、不会缩水。

8. **`width` 对 `pageup` / `pagedown` / `upper-track` / `lower-track` / `thumb` 无效**：这五块宽度恒等于整条宽度（整条宽度由 `tool.style.width` 的对应档位决定，全部按钮铺满同一宽度），在按钮的 `style` 里写 `"width": "100px"` 既不报错也不生效，属于无害字段。想改整条宽度，改皮肤 `tool.style.width`。

7. 想微调贴图位置就用 `background-position-x: 0px; background-position-y: -6px` 这种写法逐像素挪，不用改图。

**鼠标指针（**`cursor`**）**

指针由皮肤决定，`default` 状态写在哪个区、`mouseover`/`dragup`/`dragdown` 状态写什么，就显示什么：



| 场景              | 读哪个状态                                   | 皮肤没写时的默认       |
| --------------- | --------------------------------------- | -------------- |
| 移到 A / B        | A、B 的 `mouseover`，其次 `default`          | 手形 `pointer`   |
| 移到 K            | K 的 `mouseover`，其次 `default`            | 手形 `pointer`   |
| 按住拖动 K（拖出条外也一样） | K 的 `dragup`，其次 `dragdown`，再次 `default` | 手形 `pointer`   |
| 移到滑轨 F          | F 的 `default`                           | 普通箭头 `default` |
| 松开 K（指针还在 K 上）  | 回到 `mouseover` 那条                       | 手形             |

指针只用**系统自带光标**和**皮肤目录里的光标文件**，程序不自己画光标图形。Windows 光标库里没有 grabbing（抓取）这个形状，所以 `grabbing`、`grab` 一律按系统手形显示。想让某个区用你自己的光标图，把 `.cur`/`.ico`/`.ani` 放进皮肤目录，写 `"cursor": "url(小狗旺旺/grab.cur)"` 即可（相对 `.skin` 所在目录，改文件后自动重新加载）。

**状态优先级**（A/B 两区）：`doubleclick`（双击后闪 600ms）> `click`（自动滑动中）> `mouseover` > `attop`/`atbottom`（已经到顶 / 到底）> `mousedown` > `default`；K：`dragup`/`dragdown` > `mousedown` > `mouseover` > `default`。鼠标压在 A/B 上时，`mouseover` 一定看得见，不会被「已到顶 / 已到底」的样式挡掉。某状态没写 `background-image` 就沿用上一层的图，没写 `height` 就沿用 `default` 的高度（K 拖动状态若写了 `height` 就按它定高，没写按拖动图原始比例定高）。

**鼠标移开一定回到 `default`**：指针离开条（含直接跳到别的窗口、被其他窗口盖住、拖 K 到条外再松手）时，`mouseover` 立即作废，该区回到 `default` 样式，长高的部分平滑缩回；不会出现「鼠标已经走了、按钮还亮着」的残留。实现上除了鼠标离开消息，程序每 0.6 秒还会核对一次指针是否还在条内，双重兜底。

**容错**：解析器容忍裸键名、单引号、`;` 分隔、尾逗号、`//` 和 `/* */` 注释，所以你的写法里出现的 `border:none,`、`background-images:none` 这类也能读。

**旧格式兼容**：`.skin` 里第一行不是 `{` 的（早期 `A.fill=…` 那种 ini 写法）仍按旧解析器读，不会被丢弃。

**没写就不画（保持透明）**：这一条是硬规则，皮肤里没声明的东西一律不绘制 ——



| 皮肤里没写的                       | 结果                          |
| ---------------------------- | --------------------------- |
| `tool.style.background`      | 整条不铺底色，完全透明（只看得见各区的图片 / 颜色） |
| `tool.style.border`          | 不画外框，没有那圈 1px 描边            |
| 某区的 `style.background`       | 该区不铺底色，只剩图片（透明像素就透到桌面）      |
| 某区的 `style.background-image` | 该区只有颜色 / 文字，没有图             |
| `style.opacity`              | 默认 100%（不透明）                |

所以做图片皮肤时，`tool` 段只写 `width` 和 `border-radius` 就够了，图片自己就是外观；纯色皮肤（如内置的默认皮肤、北国风光）才需要显式写 `background` 和 `border`。

**高度联动规则**：整条改高时，只有 **F（轨道）** 伸缩，A/B/K 的高度保持不变。

**滑轨拆两段（**`F1`**&#x20;/&#x20;**`F2`**）**：默认整条 F 是一块。如果在 `buttons` 里另外写了 `name: "F1"` 和 / 或 `"F2"`，滑轨就变成两段、两套样式：



| 名字   | 位置                  | 说明                            |
| ---- | ------------------- | ----------------------------- |
| `F1` | A 的底边 → K 的**垂直中心** | 上半轨，跟着 K 上下移动，高度 = K 中心到 A 底边 |
| `F2` | K 的**垂直中心** → B 的顶边 | 下半轨，高度 = B 顶边到 K 中心           |

几条要点：



1. **接缝就在 K 的中间**：两段的交界永远落在 K 的垂直中心线上，K 上下移动时接缝跟着走，所以 K 永远「压」在两段的交界处。

2. **无缝**：接缝两侧都取平边（圆角只作用于各自的外侧两端），且按整像素切分，中间不会出现 1px 亮线或空隙。

3. **`thumb` 浮在上面**：绘制顺序是 upper-track → lower-track → pageup/pagedown → thumb，`thumb` 永远是最后画的，所以它的图（含半透明）会盖住两段，不会被轨道切掉。

4. **只写一半也行**：只写 `upper-track` 就上半轨用新样式、下半轨继续用 `track` 的样式（反之亦然）；两个都不写就是原来的整段轨道，老皮肤外观完全不变。

5. **名字别名**：`upper-track` 也可写成旧名 `F1` / `F-up` / `F-TOP` / `FU` / `F-BEFORE`；`lower-track` 可写成 `F2` / `F-down` / `F-BOTTOM` / `FD` / `F-AFTER`。整条轨道叫 `track`（旧名 `F`），滑块叫 `thumb`（旧名 `K`），上下按钮叫 `pageup` / `pagedown`（旧名 `A` / `B`）。

6. 两段各自支持 `background` / `background-image` / `background-repeat` / `background-size` / `background-position(-x/-y)` / `opacity` / `border-radius` / `cursor`，以及 `mouseover`、`mousedown` 状态（悬停按鼠标在 K 上方还是下方判断是哪一段）。

7. 用一条竖纹图做「整条轨道纹理」的标准写法（等比例放大到条宽再纵向平铺，不压扁、不接缝）：

```json
{ "name": "upper-track", "action": "default", "style": { "background-image": "url(北国风光/a_mid.png)", "background-repeat": "repeat-y", "background-size": "100% auto" } }
```



```
"buttons": [
  { "name": "track",  "action": "default", "style": { "background": "none" } },
  { "name": "upper-track", "action": "default", "style": { "background-image": "url(小狗旺旺/up_track.png)", "background-repeat": "repeat-y", "background-size": "auto" } },
  { "name": "lower-track", "action": "default", "style": { "background-image": "url(小狗旺旺/down_track.png)", "background-repeat": "repeat-y", "background-size": "auto" } }
]
```

## 五、状态与声音



1. 静止 —— 默认外观，静音

2. 点中目标窗口 —— **静默**（点屏幕任何地方都不会出声，只默默记住目标窗口，下次操作就作用在它上面）

3. 单击 A / B（启动自动滚动）—— 该区 `click` 样式 + `autoStart.wav`

4. 再单击 A / B（停止）—— 恢复默认 + `autoStop.wav`

5. 双击 A / B —— `doubleclick` 样式闪 600ms（内置小狗皮肤会闪一格卧狗图）+ `clickAB.wav`，同时一步到顶 / 到底

6. 已经到顶 / 到底 —— 该区 `attop` / `atbottom` 样式（内置皮肤变暗到 55%）+ 静音

7. 点 K —— 按下反馈 + `clickK.wav`

8. 拖动 K 向上 —— `dragup` 样式 + `dragUp.wav`

9. 拖动 K 向下 —— `dragdown` 样式 + `dragDown.wav`

10. 鼠标移到 A / B —— `hoverAB.wav`

11. 鼠标移到 K —— `hoverK.wav`

12. 鼠标移出 A / B —— `leaveAB.wav`

13. 鼠标移出 K —— `leaveK.wav`

悬停音规则：只在「A/B 组 ↔ K ↔ 轨道 / 空白」之间切换时响；在同一组内部移动（例如 A 移到 B）不重复响。悬停音是更短更轻的 45–50ms 轻点声，不会盖过点击音。

拖动 K 时**同一个方向只响一次**：一路往下拖只 “咔” 一声，往上拖也只响一声；只有中途反方向了才会再响一次，不会跟着滑块一路连响。

**A / B 自动滑动时 K 也跟着变**：单击 A（自动向上）期间，K 一律使用皮肤的 `dragup` 状态（图、颜色、高度都按该状态），并按滚动比例实时上移；单击 B（自动向下）期间用 `dragdown` 状态并实时下移；再点一次停下或滑到顶 / 底时，K 立即回到 `default` 状态。也就是说 `dragup` / `dragdown` 同时服务于 “手拖” 和 “自动滑动” 两种情形，不需要额外再做一套状态。

**点 K 会接管自动滑动**：A 或 B 正在自动滑动时，只要在 K 上按下（点击或开始拖动），自动滑动立刻停止，改由手拖 K 控制；点滑轨 F 跳转同理。

**悬停是有过渡动画的**：`mouseover` 的样式不会「啪」地切换，而是随鼠标进入分 5 步渐变显示 —— 如果 `mouseover` 写的是 `height`，A/K/B 会**平滑长高**（下方分区跟着顺移，离开时再平滑缩回）；如果写的是 `background` 或 `background-image`，颜色 / 图会**淡入**；如果只是 `opacity` 不同，就直接插值透明度。三套内置皮肤已经给 A/K/B 都写了 `mouseover`（小狗旺旺与北国风光是长高＋换图，默认皮肤是变青灰＋长高），所以鼠标移上去能看到「动」。

**默认是「叠画」，过渡时长 / 硬切换由皮肤的 `transition` 决定**：引擎默认把 `mouseover` 叠在 `default` 之上淡入 —— `default` 先按满不透明度铺底，`mouseover` 再按进度盖上去，所以 `mouseover` 的 `opacity` 不是 100% 时能看见底色透出来（这正是渐变效果）。想让某个状态**单独显示、完全不叠底**（硬切换、不淡入，`mouseover` 的透明处直接透到桌面），就在那个 `action` 的 `style` 里写：

```json
"transition": "none"
```

`transition` 写法的规则（写在哪个 `action` 的 `style` 里，就只管那个状态）：

| 写法 | 效果 |
| --- | --- |
| 不写 | 引擎默认：叠画 + 约 165ms 淡入（即 `165ms`） |
| `none` / `0` / `0ms` / `"0s"` | **硬切换**：不淡入、不叠 `default` 打底，只画 `mouseover` 自己（透明区透到桌面） |
| `120ms` / `0.2s` / `200`（纯数字按毫秒） | 叠画 + 按这个时长淡入（时长越短越「干脆」） |
| `all .2s ease` 这类多段写法 | 取其中的时间部分，与 `0.2s` 等价 |

例：A 区「悬停时整块换成另一张图、不要看见底图」：

```json
{ "name": "pageup", "action": "mouseover", "style": { "transition": "none", "background-image": "url(小狗旺旺/bigbar1_1.png)" } }
```

实测证据（同一套皮肤、只差 `transition`）：A 常态红 `#CC0000`、`mouseover` 蓝 `#0000FF` + `opacity 55%`。叠画版悬停后中心像素由 `R205 G3 B3` 变成 `R94 G3 B141`（红底上盖 55% 蓝）；写了 `"transition": "none"` 的硬切版同一位置变成 `R117 G117 B255`（只剩蓝、红底完全不见）。

**图集皮肤（一张图里有多格状态）也能靠 `mouseover` 换格**：`background-position`、`background-position-x/-y`、`background-size`、`background-repeat` 任意一项不同，就算「换了样式」，会按过渡淡入显示；哪怕 `background-image` 是同一个文件名（`bigbar1.png` 只改 `-100px 0px` 去选第二格），也一样生效 —— 不用为了悬停专门拆出另一张图。

**没设状态就没有视觉变化**：`mouseover` / `mousedown` / `dragup` / `dragdown` 如果皮肤里没写，鼠标移上去、按下去、拖动时外观**一点都不会变**（不会提亮、不会微放大、不会有内置高亮），只有该状态的音效照常播放。拖动 K 时也一样：皮肤没写 `dragup` / `dragdown`，K 的高度、颜色、图片全部保持 `default` 原样，只有位置随滚动比例移动。想让 K 悬停或拖动有反馈，就在皮肤里写对应 `action` 的样式。

**自动滑动中 A / B 的样式**：用该区 `click` 状态；双击瞬间用 `doubleclick` 状态闪 600ms；到顶 / 到底后转 `attop` / `atbottom`。三种都写了才有变化，没写就保持 `default`。

声音只在「操作滚动条本身」时发出：点 A/B、点 K、拖 K、鼠标移入移出各功能区、菜单操作。点击桌面或其他窗口一律静音。

**音效由皮肤预设，用户不需要（也不能）逐个设置。** 每套皮肤自带一整套 14 个音效，切换皮肤会连音色一起换：



| 皮肤   | 音色           |
| ---- | ------------ |
| 默认皮肤 | 标准清脆点击声（基准）  |
| 小狗旺旺 | 偏高偏脆、短促，像小奶音 |
| 北国风光 | 偏低偏长、清冷柔和    |

音效文件在 `%AppData%\BigBar\sounds\<皮肤名>\`（每套皮肤一个文件夹，14 个 wav）。右键菜单「声音」只有 **开 / 关** 一个开关，关掉就全局静音。

## 六、常见问题

**滚动没反应？** 先点一下目标窗口（让它成为最后点击的窗口），再点 A/B 或拖 K。记事本、Chrome、VS Code、Word、Foxit 等已验证可用。

**方向反了？** 部分浏览器 / 内嵌页面的滚动方向与桌面控件相反，可在 `%TEMP%\BigBar.log` 看 `状态 ratio=` 采样判断，必要时在菜单里用「位置 → 自定」或「横向距离 / 纵向距离 → 自定义」把条重新摆一下，或联系作者。

**装不上 / 文件被占用？** 先退出正在运行的 BigBar（托盘右键退出），再运行安装包；安装器会自动结束旧进程并清理旧版残留。

**端口 / 网络类提示：**「添加皮肤」需要联网，失败时不影响本地使用。托盘「使用说明」会直接用浏览器打开 <https://yahooeatapple.github.io/BigBar>。

**语言切了但皮肤名没变？** 皮肤名的显示名来自皮肤文件顶层的 `language`（`en` / `zh` / `es`）；三样都没写的皮肤会一直显示它的 `name`。自己写的皮肤补上 `"language": { "en": "...", "zh": "...", "es": "..." }` 再在菜单里重选一次这套皮肤即可，不用重启。

**选了某套皮肤，工具却长得像一条「测试用的简易条」？** 先看那套皮肤的 `.skin` 文件本身，看两项：

1. `"width"` —— 74 / 72 这种窄值 + 文件里**没有任何 `url(`** = 这是程序生成的简化配色版（只有底色、顶/底字样），不是你的图片皮肤；
2. 所有 `url(...)` 指向哪个目录 —— 若指向 `BBB/…`、`CCC/…` 这类试验图集，画出来的自然就是试验条。

历史上最可能的成因是**旧版把你这套皮肤当成自带皮肤重写了**（旧版只按文件里有没有「官方」两字判断）。现在升级只认 `"generatedby": "gunbar"` 标记，你自己的文件不会再被动；被覆盖过的旧内容可以在同目录找到 `皮肤名.skin.bakN`（编号越大越新），把它拷回去即可恢复原状。

### 从旧版「滚一下 Gunbar」升级上来会怎样

- 老版本装在 `%LocalAppData%\Programs\Gunbar`，新版装在 `...\Programs\BigBar`；安装器会结束旧进程、删掉旧目录 / 旧快捷方式 / 旧自启项 / 旧卸载项，不会同时留两个。
- **你的设置不会丢**：注册表 `Software\Gunbar`（或更早的 `Software\BigScrollBar`）里的尺寸、皮肤、透明度、语言等，会在新版第一次启动时整份继承过来，并立刻写入新键 `Software\BigBar`。
- **你的皮肤不会丢**：`%AppData%\Gunbar`（或 `%AppData%\BigScrollBar`）整个目录会在新版第一次启动时递归复制到 `%AppData%\BigBar`，同名文件不覆盖；原目录保持原样，确认没问题后可自行删除。
- 自启项名从 `Gunbar` 改为 `BigBar`，`Gunbar` / `BigScrollBar` 的老值会被清掉；快捷方式从「滚一下.lnk」变为「BigBar.lnk」。

版本 1.1.4
